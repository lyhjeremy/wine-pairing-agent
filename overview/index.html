Wine Pairing Agent
Reasons about the dish, then retrieves

A LangGraph agent with retrieval as a tool

Name a dish. It works out the wine style, then finds bottles that fit it.

Given "grilled ribeye steak with a peppercorn cream sauce" and a $45 budget, the agent reasoned to a full-bodied, tannic Cabernet, searched the Wine Enthusiast review index through a LangChain StructuredTool, got six Cabernets back inside the budget, and recommended two with citations. A critique node then checked the pairing; had it found a problem, it would have sent the agent back to try another style.

The problem

A dish is not a search query

The sibling project, Wine Sommelier RAG, answers requests that already contain their search terms: "a bold red under $25" is close to a query. "Grilled ribeye with peppercorn sauce" says nothing about tannin or dark fruit, so a retriever has nothing to match on.

This agent reasons about the dish first, picks a target style from a short list of pairing principles in src/pairing.py (acid cuts fat, tannin binds protein, match weight, sweetness tames heat, regional dishes with regional wines), writes a search query for that style, and only then calls retrieval. Afterwards it checks its own answer.

Course by course

One run through the five nodes

Step through the recorded ribeye run from examples/sample_run.md. Each node's width in the strip is its time in the traced ribeye run in the README (same $45 budget, shorter wording of the dish): 9.0 seconds in all, of which the local search took 0.3. The retrieve segment is drawn wider than its share so its label fits. On a phone the strip shows node numbers only.

0 s9.0 s

The retrieve step ranks 40 candidates by 0.8 × cosine similarity + 0.2 × rating, with the rating scaled so 80 points is 0 and 100 is 1. On that blend a 95-point wine beats a 92-point one only if its similarity is no more than 0.0375 lower, so the rating breaks near-ties and does not override the match.

Observability

Every run can be traced and timed

Because retrieve is a named LangChain tool, it shows up in a trace as a tool call. --trace times each node, prints a trace tree, and saves the run as JSON under traces/. The traced ribeye run behind the strip above, as recorded in the README with its bullet glyphs dropped: 

AGENT TRACE  (node · time · detail)
  parse         1.2s   ribeye · rich body
  strategize    2.3s   style → full-bodied tannic red
  retrieve      0.3s   6 candidate wines (tool: search_wines)
  recommend     3.0s   drafted pairing with citations
  critique      2.2s   sound

Nearly all the latency is the four LLM calls. When critique sends the agent back to strategize, the second pass appears in the same trace.

Limitations

It works and checks itself; nobody has scored it

There is no scored evaluation of pairing quality here, unlike the retrieval benchmark in the sommelier project. Pairing has few single right answers, which makes it harder to score, though that explains the gap without closing it. This page shows a traced agent that checks itself; it does not show that its pairings beat a human's or a simpler baseline. The walkthrough is one recorded run, and the timings come from a separate traced run of a similar ribeye request.

assets/make_trace_figure.py can draw a saved trace as a timeline, but no rendered timeline from a live run is in the repository. The pairing principles are a short list, so fortified wines, very hot food and dessert courses get thinner treatment. Retrieval filters on price only; a color preference reaches the agent through the query and the critique, with no hard filter behind it. The index holds the 30,000 highest-scored reviews by default.

How it was built

Stack

Agent
LangGraph StateGraph with five nodes and a conditional retry edge (src/graph.py)
Tool
src/tools.py wraps retrieval as a LangChain StructuredTool with a typed schema
Index
Wine Enthusiast reviews embedded with sentence-transformers and stored in Chroma; 30,000 by default, --all for the full 129,971
Generation
Claude through the Claude CLI by default; ANTHROPIC_API_KEY switches to the API
Tracing
src/trace.py: per-node timing, a tree view, JSON output
Related
Wine Sommelier RAG supplies the retrieval; the Training Plan Agent uses the same critique loop
