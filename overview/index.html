Wine Pairing Agent
Reasons about the dish, then retrieves

A LangGraph agent with retrieval as a tool

Name a dish. It works out the wine style, then finds bottles that fit it.

On a frozen set of dishes, the agent's first pick was a grape the dish calls for in all 4 dishes it ran; searching the reviews with the dish text alone managed 3 of those 4, and 3 of all 10. Each pairing cost $1.25 at API prices and took 78 seconds, because the critique node rejected all 12 drafts it saw and used up both retries every time.

The agent reasons from the dish to a wine style, searches the Wine Enthusiast review index through a LangChain StructuredTool with the budget as a filter, recommends with citations, and sends itself back when its critique finds a problem.

The problem

A dish is not a search query

The sibling project, Wine Sommelier RAG, answers requests that already contain their search terms: "a bold red under $25" is close to a query. "Grilled ribeye with peppercorn sauce" says nothing about tannin or dark fruit, so a retriever has nothing to match on.

This agent reasons about the dish first, picks a target style from a short list of pairing principles in src/pairing.py (acid cuts fat, tannin binds protein, match weight, sweetness tames heat, regional dishes with regional wines), writes a search query for that style, and only then calls retrieval. Afterwards it checks its own answer.

Course by course

One run through the five nodes

Step through the recorded ribeye run from examples/sample_run.md. Each node's width in the strip is its time in the traced ribeye run in the README (same $45 budget, shorter wording of the dish): 9.0 seconds in all, of which the local search took 0.3. The retrieve segment is drawn wider than its share so its label fits. On a phone the strip shows node numbers only.

0 s9.0 s

The retrieve step ranks 40 candidates by 0.8 × cosine similarity + 0.2 × rating, with the rating scaled so 80 points is 0 and 100 is 1. On that blend a 95-point wine beats a 92-point one only if its similarity is no more than 0.0375 lower, so the rating breaks near-ties and does not override the match.

The scored run

Ten dishes, one answer key, written first

Error analysis

The critique rejected every draft, mostly for the wine's age

The critique node passes a pairing only when its LLM review lists no issues. In the 4 scored runs it listed issues in all 12 rounds, so every run went parse, then three rounds of strategize, retrieve, recommend and critique, and stopped at the attempt limit with the issues still open. Grouping the first issue of each round, and every issue in each run's last critique (eval/critique_issues.json, coded by hand):

Kind of issueFirst, of 12Last, of 19
The vintage is too old to trust the note76 "The 2007 JD will be about 19 years old in 2026. Its tannins have probably softened since release." (ribeye)
Quibble with one line of the explanation28 "'Searingly tart' wine next to a red wine vinegar mignonette risks stacking acid on acid." (oysters)
A different grape or weight would suit better24 "A Spätlese or a fuller off-dry Riesling would match the weight better." (green curry)
Asked for a style the index can't supply11 "The user asked for Nebbiolo and a recent vintage. Neither request is met." (risotto)

The age complaint can't be fixed by retrying. No vintage in the review file is newer than 2017, the newest of the 24 retrieved bottles was 2016, and after the first rejection strategize starts asking for "a recent vintage", which sends the search after wines the index does not have. The critique prompt has no notion that the index is a snapshot, and no rule says which issues are worth a retry. The July recorded run above passed on its first critique; on 2026-11-05 none did.

Cost and latency

$1.25 and 78 seconds a pairing, most of it CLI overhead

Measured on 2026-11-05 on an Apple M4 by running the agent through eval/run_eval.py, which adds --output-format json to the agent's own Claude CLI calls and keeps the reported cost and duration. The cost is the API-equivalent figure the CLI reports; it runs on a Claude subscription, so nothing was billed. The CLI's default model was Opus 5.5.

Per pairing
$1.25 median, $1.23 to $1.31 (n = 4); 77.9 s median, 79.7 s p95; 10 LLM calls each
Per call
$0.11 to $0.14 and 2.6 to 9.8 s (risotto run, eval/calls.csv). Each call read about 13,300 cached tokens and wrote 12,100 to 15,300 more: the CLI's own system prompt and context. The agent's prompt and the reply are a few hundred tokens
Retrieval
The local search is not an LLM call; it took 0.3 s in the traced run
Not measured
The Anthropic API backend in src/llm.py, which sends only the agent's prompt; there is no API key here to measure it

Two things set the bill: the retry loop that never exits early (10 calls where 4 would do), and the CLI's context on every call. A pairing that passed its first critique would make 4 calls.

Observability

Every run can be traced and timed

Because retrieve is a named LangChain tool, it shows up in a trace as a tool call. --trace times each node, prints a trace tree, and saves the run as JSON under traces/. The traced ribeye run behind the strip above, as recorded in the README with its bullet glyphs dropped: 

AGENT TRACE  (node · time · detail)
  parse         1.2s   ribeye · rich body
  strategize    2.3s   style → full-bodied tannic red
  retrieve      0.3s   6 candidate wines (tool: search_wines)
  recommend     3.0s   drafted pairing with citations
  critique      2.2s   sound

Nearly all the latency is the four LLM calls. When critique sends the agent back to strategize, the second pass appears in the same trace.

Limitations

Scored on 4 dishes, with a key I wrote

The scored run covers 4 dishes for the agent and 10 for the baseline, against an answer key of accepted grapes that I wrote from standard pairing rules. Pairing has few single right answers, so a grape match is a floor, not a judgment of the pairing; no sommelier or blind tasting checked the picks. The walkthrough above is one recorded run from July, and its timings come from a separate traced run of a similar ribeye request.

assets/make_trace_figure.py can draw a saved trace as a timeline, but no rendered timeline from a live run is in the repository. The pairing principles are a short list, so fortified wines, very hot food and dessert courses get thinner treatment. Retrieval filters on price only; a color preference reaches the agent through the query and the critique, with no hard filter behind it. The index holds the 30,000 highest-scored reviews by default.

How it was built

Stack

Agent
LangGraph StateGraph with five nodes and a conditional retry edge (src/graph.py)
Tool
src/tools.py wraps retrieval as a LangChain StructuredTool with a typed schema
Index
Wine Enthusiast reviews embedded with sentence-transformers and stored in Chroma; 30,000 by default, --all for the full 129,971
Generation
Claude through the Claude CLI by default; ANTHROPIC_API_KEY switches to the API
Tracing
src/trace.py: per-node timing, a tree view, JSON output
Related
Wine Sommelier RAG supplies the retrieval; the Training Plan Agent uses the same critique loop
